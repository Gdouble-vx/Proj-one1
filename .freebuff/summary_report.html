1. บทนำและปัญหา

1.1 ภาพรวมโครงการ

โครงการนี้มุ่งพัฒนาระบบเลือกเส้นทางอัตโนมัติบนเครือข่าย Software-Defined Networking (SDN) โดยใช้เทคนิค Deep Reinforcement Learning (DRL) ร่วมกับ Graph Neural Network (GNN) เพื่อแก้ไขปัญหาคอขวดและเพิ่มประสิทธิภาพการส่งข้อมูลในเครือข่าย

1.2 ปัญหาที่พบ

โปรโตคอล OSPF (Open Shortest Path First) ซึ่งเป็นวิธีดั้งเดิม มีข้อจำกัดสำคัญ 3 ประการ:

  • ใช้ hop-count เป็นเกณฑ์ — ไม่พิจารณาความจุของลิงก์ ทำให้ส่งข้อมูลผ่านลิงก์แคบ (15 Mbps) ทั้งที่มีลิงก์กว้าง (200 Mbps) ทางอื่น
  • ไม่ปรับตัวตามสภาพจราจร — ไม่สามารถตอบสนองต่อการเปลี่ยนแปลงของโหลดในเครือข่ายได้
  • ประสิทธิภาพต่ำบน topology ที่ไม่สมมาตร — มี packet loss สูงถึง 18.5% บน NSFNET topology

1.3 วัตถุประสงค์

เป้าหมาย: พัฒนา AI agent ที่สามารถเรียนรู้และเลือกเส้นทางที่เหมาะสมกว่า OSPF/ECMP และวิธี DRL อื่นๆ บน topologies มาตรฐาน

องค์ประกอบรายละเอียด

เวลาเทรน131.4 นาที (CPU)

3.2 Reward Shaping 4 องค์ประกอบ

total_reward = metric_reward + exploration_bonus + diversity_bonus + novelty_bonus + improvement_bonus
  • metric_reward: (throughput^1.2 / latency) / 1e5 — รางวัลตามประสิทธิภาพ
  • exploration_bonus: 0.5 × mean(|action - prev_action|) — รางวัลการเปลี่ยนน้ำหนัก
  • diversity_bonus: 0.3 × std(action) — รางวัล action ที่ไม่ uniform
  • novelty_bonus: 0.05 × mean(|action - baseline|) — รางวัลการห่างจาก OSPF

  1. PPO+GNN ชนะทุกวิธี — throughput สูงสุด +6.66%, loss ต่ำสุด -28.8% บน NSFNET topology
  2. โมเดล converge ใน 50k steps (~2 ชม. CPU) ด้วย monotonic improvement
  3. AI เรียนรู้ inverse-BW weighting — ลิงก์แคบได้น้ำหนักสูง (80.5), ลิงก์กว้างได้น้ำหนักต่ำ (1.1)
  4. Zero-shot ล้มเหลว — GNN ไม่สามารถโอนย้ายข้าม topology ได้ (ต้อง fine-tune)
  5. Fine-tune เท่ากับ From Scratch — PPO+GNN เรียนรู้ optimal routing บน topology ใหม่ใน 5k steps

9.2 สรุป贡献

  • ✅ Reward Shaping 4 องค์ประกอบ — แก้ปัญหา safe-action plateau ที่ agent เลือกไม่เปลี่ยนเส้นทาง
  • ✅ Transfer Learning Pipeline — pretrain → freeze GNN → fine-tune policy head
  • ✅ การทดสอบข้าม Topology — NSFNET → Abilene zero-shot + fine-tune evaluation
  • ✅ การเปรียบเทียบ 11 วิธี — fair comparison บน simulator/seeds/traffic เดียวกัน
  • ✅ Real ONOS Evaluation — ทดสอบโมเดล 100k steps บน Mininet+ONOS 2.7.0

9.3 ข้อจำกัดและงานต่อไป

  • Zero-shot transfer ยังล้มเหลว — ต้องพัฒนา topology-agnostic GNN ที่ generalize ได้ดีกว่า
  • ONOS 2.7.0 มี OF version mismatch (OF1.5 vs OF1.3) — ต้อง upgrade OVS หรือใช้ ONOS เวอร์ชันที่ compatible
  • โมเดล 100k steps บน ONOS จริงยังเล่น safe (action = 1.0 ทุกลิงก์) — ต้องปรับ reward shaping เพิ่ม
